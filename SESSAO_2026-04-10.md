# Sessão 2026-04-10 — Criação do Local Shell MCP Server

## Objetivo da sessão

Criar um MCP server local que permitisse ao Claude executar comandos no terminal do Mac do Márcio, como se fosse o próprio utilizador a fazê-lo — sem restrições de comandos.

---

## O que foi feito

### 1. Decisões iniciais (via AskUserQuestion)
- Formato: **Plugin Cowork** (tentativa inicial)
- Funcionalidades: `execute_command` simples, sem extras
- Segurança: sem restrições (zero whitelist/blacklist)

### 2. Primeira abordagem — Plugin Cowork (falhou)
Criou-se um plugin Cowork com um MCP server Node.js embutido. O plugin foi instalado com sucesso no Cowork. No entanto, ao tentar correr comandos, o servidor estava a correr dentro da **sandbox do Cowork** (Linux/arm64), não no Mac local do utilizador:

```
hostname: claude
user: happy-tender-fermi
home: /sessions/happy-tender-fermi
```

Diagnóstico: os MCP servers definidos em plugins Cowork são sempre executados no ambiente sandboxed remoto, não na máquina local do utilizador. Limitação arquitetural — não é um bug.

### 3. Tentativa de computer-use no Terminal (falhou)
Tentou-se usar o computer-use para abrir o Terminal do Mac e escrever comandos. O Terminal foi aprovado mas com tier **"click"** (sem acesso a teclado), o que impossibilita a escrita de comandos. Limitação de segurança do Cowork.

### 4. Solução correta — MCP server configurado localmente
O `shell-server.js` foi copiado para a máquina local e configurado diretamente no `claude_desktop_config.json`:

```json
"local-shell": {
  "command": "node",
  "args": ["/Users/marciomartins/Documents/Local-shell/shell-server.js"]
}
```

Desta forma o server corre nativamente no macOS, com acesso real ao sistema de ficheiros e terminal do utilizador.

**Teste confirmado:**
```
hostname: MacBook-Pro-de-Marcio-2.local
user: marciomartins
os: Darwin 25.3.0
```

### 5. Limpeza — Plugin Cowork desinstalado
O plugin que não funcionava foi removido manualmente via `mcp__local-shell__execute_command`:
- Pasta `plugin_014ZSWPu1f11DNs3R3EwK61v` apagada de `rpm/`
- Entrada removida do `rpm/manifest.json`

### 6. Criação do projeto no Cowork
A pasta `/Users/marciomartins/Documents/Local-shell` foi adicionada à lista `localAgentModeTrustedFolders` no `claude_desktop_config.json` — o que cria automaticamente um projeto Cowork associado à pasta.

## Estado atual do servidor (`shell-server.js`)

Versão funcional com 3 tools:

| Tool | Descrição |
|------|-----------|
| `execute_command` | Executa qualquer comando shell; devolve stdout, stderr, exit code |
| `get_system_info` | Info do sistema (OS, user, shell, memória, etc.) |
| `http_request` | Pedidos HTTP/HTTPS via curl — útil para aceder a `localhost` ou redes privadas inacessíveis na sandbox |

Zero dependências npm. Comunicação JSON-RPC 2.0 sobre stdio.

---

## Lições aprendidas

1. **Plugins Cowork ≠ MCP local** — MCP servers em plugins correm na sandbox remota. Para acesso à máquina local, o server tem de estar configurado no `claude_desktop_config.json` do Claude Desktop.

2. **Terminal via computer-use tem tier "click"** — não é possível escrever comandos em apps de terminal via computer-use. Usar `mcp__local-shell__execute_command` para tudo o que seja shell.

3. **`mcp__local-shell__execute_command` é o tool certo** para qualquer operação no Mac do Márcio — ficheiros, processos, scripts, configurações do sistema, etc.
